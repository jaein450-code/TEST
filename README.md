# 맛집노트 · ONTO INNOVATION

서버 배포 안내와 메일·영구 저장 설정은 [DEPLOY.md](DEPLOY.md)를 참고하세요.

Node.js 22.13 이상이 필요하며 별도 패키지 설치는 없습니다. SQLite는 Node 내장 모듈을 사용합니다.

```sh
npm start
```

기본 포트는 3000입니다. `npm run dev`는 자동 재시작, `npm test`는 인증·리뷰 검증 테스트, `npm run build`는 로그인 화면 파일 미리보기 생성입니다. 기존 체크아웃에서 작업하며 별도 Git worktree는 필요 없습니다.

## 회사 이메일 가입 및 로그인

- 정확히 `@ontoinnovation.com` 도메인만 서버에서 허용합니다. 하위 도메인이나 유사 도메인은 거절합니다.
- 이메일의 6자리 일회용 인증번호를 입력하면 최초 계정 생성과 로그인을 함께 처리합니다. 비밀번호는 없습니다.
- 인증번호 10분 만료, 최대 5회 오입력, 재발송 간격 60초, 이메일당 시간당 5회·접속 IP당 20회 발송 제한을 적용합니다. 역방향 프록시 뒤에서는 공통 IP로 제한될 수 있습니다. 전달 헤더를 무조건 신뢰하지 않습니다.
- 로그인 세션은 8시간 유효하며 HttpOnly/SameSite 쿠키로 전달합니다. 운영 모드에서는 Secure 쿠키를 사용합니다. 로그아웃하면 서버 세션을 폐기합니다.
- 비로그인 사용자는 로그인 화면만 볼 수 있고 앱 스크립트와 예시 맛집 데이터 경로도 차단됩니다.
- 계정·인증번호 해시·세션 해시는 `.local/auth.sqlite`에, 직원 등록 매장과 공유 리뷰는 `.local/dining.sqlite`에 저장됩니다. DB와 디렉터리는 웹에 공개하지 마세요. 영구 볼륨에 보존하고 접근을 제한하세요. 다중 서버 배포에는 공유 인증 저장소와 공유 요청 제한이 필요합니다.
- 메일함 소유 확인이며 회사의 재직자 명부 조회는 아닙니다. 퇴사 즉시 차단·중앙 계정 회수에는 회사 SSO 또는 별도 관리 기능이 필요합니다. 현재 이미 발급된 세션은 최대 8시간 유지됩니다.

## 메일 발송 설정

메일 발송이 설정되지 않으면 인증 요청은 503으로 실패하며 가입되지 않습니다. 실제 메일 발송은 아직 검증하지 않았습니다.

현재 Resend 연결 코드를 제공합니다. 운영자가 사용 권한을 가진 별도 발신 도메인과 주소를 결정하세요. 가입자의 회사 이메일은 수신용으로만 사용합니다. 별도 도메인을 쓰면 회사 도메인 DNS나 회사 메일 발송 계정을 연결할 필요가 없습니다. Resend를 쓸 경우 운영자가 관리하는 발신 도메인을 서비스에서 인증하고, 다음 값을 배포 환경에 안전하게 설정하세요. 비밀 키를 채팅이나 Git에 올리지 마세요.

- `RESEND_API_KEY`: 메일 발송 API 키
- `AUTH_MAIL_FROM`: 서비스에서 인증한 앱 전용 발신 주소(회사 주소일 필요 없음)
- `NODE_ENV=production`
- `PUBLIC_ORIGIN`: 외부 접속 HTTPS 주소(경로·끝 슬래시 없이)
- 아웃바운드 HTTPS `api.resend.com` 허용 및 외부 HTTPS 배포 필요

회사에서 다른 발송 서비스나 SMTP만 허용한다면 메일 전송 어댑터를 해당 방식으로 교체해야 합니다. `.env` 파일은 자동 로드하지 않습니다. 셸 또는 호스팅 설정을 사용하세요.

## 실제 메일 없는 로컬 개발

```sh
AUTH_DEV_MAIL=1 npm start
```

이 모드에서는 루프백 주소에만 서버를 바인딩하고 실제 메일을 보내지 않습니다. `@ontoinnovation.com` 주소로 요청 후 `.local/development-mail.json`에서 개발 인증번호를 확인할 수 있습니다. 파일은 HTTP로 제공되지 않습니다. 운영 모드에서는 이 옵션이 무시됩니다. 개발 모드를 공개 배포하지 마세요.

## 미리보기 및 맛집 기능

루트 `index.html`과 `preview.html`은 가상 식당만 포함하는 독립 실행 HTML 미리보기입니다. 파일 하나에 CSS·데이터·스크립트가 들어 있으며 외부 파일이나 서버 요청 없이 열립니다. 검색·조건 필터·상세 화면을 확인할 수 있지만, 맛집 등록·리뷰 공유·실제 인증은 불가능합니다. 인증된 API 응답이나 SQLite 데이터베이스는 미리보기 생성 과정에 사용하지 않습니다. 회사명은 ONTO INNOVATION 텍스트로 표시했으며 공식 로고 이미지 원본은 아직 적용하지 않았습니다.

서버에서는 `/preview`로 같은 가상 데이터 화면을 제공하고 로그인 화면에도 연결합니다. 실제 서비스의 `/`는 기존 직원 인증을 유지합니다. 외부에서 접속할 수 있는 공개 배포 주소는 아직 없습니다. 앱의 미리보기 호스트 자체에서 발생하는 ‘시각화 내부 오류’는 이 파일의 동작 확인과 별개입니다. HTML 파일을 직접 브라우저에서 열어 확인할 수 있습니다.

원본 수정 후 `npm run build`로 미리보기를 갱신하세요.

## 동탄 맛집 기능

기준 위치는 **동탄 더퍼스트타워2차**입니다. 정확한 좌표나 지도 경로를 조회하는 API는 아직 연결하지 않았습니다.

- 회사 근처 점심: 등록된 도보 시간이 15분 이내인 곳(카페 제외).
- 동료들이 추천한 곳: 직원 리뷰에 ‘재방문하고 싶어요’가 있는 곳. 추천 건수와 별점은 실제 작성된 리뷰로만 계산하며 초기 가상 별점은 표시하지 않습니다.
- 회식하기 좋은 곳: 등록된 함께 앉을 수 있는 인원이 6명 이상인 곳. 6·10·20명, 주차·예약 조건으로 좁힐 수 있습니다.
- 동네: 회사 인근, 동탄역, 북광장, 남광장, 센트럴파크, 호수공원, 기타 동탄.
- 가격: 대표 메뉴 1인 가격 기준 1만 원 이하 / 1만 초과~1만 5천 원 / 1만 5천 원 초과.
- 이동: 도보 5·10·15분 이내, 차량 10분 이내. 시간이 미확인인 매장은 해당 시간 필터에서 제외합니다.
- 직원 맛집 등록: 이름·주소·대표 메뉴·가격 필수, 이동 시간·단체 인원·주차·예약은 모르면 미확인으로 둡니다. 직원 등록 정보는 업체 검증이나 지도 자동 조회를 거친 것이 아닙니다.
- 네이버지도·카카오맵 검색 링크: 직원 등록 매장은 입력한 이름과 주소로 검색하고, 예시 매장은 해당 동네 맛집 검색으로 연결합니다. 회사 위치 링크에서 출발지를 확인하고 지도에서 경로를 설정할 수 있습니다. 외부 지도 검색 결과와 경로 계산은 앱의 검증 범위 밖입니다.
- 방문 리뷰: 방문 날짜(서울 날짜 기준, 미래 날짜 금지), 별점, 닉네임, 내용 필수. 대기·식사 소요 시간과 ‘빠르게 나와요’, ‘혼밥하기 좋아요’, ‘재방문하고 싶어요’ 태그를 추가할 수 있습니다.
- 닉네임과 리뷰는 인증된 직원들과 공유됩니다. 회사 이메일은 리뷰 응답에서 공개하지 않습니다. 본인 리뷰만 삭제할 수 있고, 식당·작성자·방문 날짜당 1개를 허용합니다.
- 서버 재시작 후 매장·리뷰가 보존됩니다. 다른 직원의 새 리뷰는 페이지를 새로고침하면 표시됩니다. SQLite 파일은 영구 저장 경로에 보존해야 합니다.
- 즐겨찾기는 계정별로 현재 브라우저에 보관됩니다. 이전 버전의 브라우저 전용 리뷰는 방문 날짜와 공유 동의가 없으므로 자동으로 서버에 올리지 않고 기존 로컬 저장소에 남겨 둡니다.

### 예시 데이터와 실제 정보 구분

기본 6개 매장은 **가상의 동탄 맛집 예시**입니다. 가격·이동 시간·단체석·주차·예약은 필터 시연용 값이며 실제 매장 정보가 아닙니다. 화면과 상세에 이를 표시합니다. ‘직원 등록만’ 필터로 예시를 제외할 수 있습니다. 예시 매장에 작성한 리뷰 역시 실제 방문 평가가 아닙니다. 실제 동탄 매장 데이터 수집이나 거리 계산을 완료했다고 간주하지 마세요.

### 검증

`npm test`는 이메일 인증, 로그인 보호, 필터 경계값·미확인 정보 처리, 리뷰 입력 검증, 두 직원 간 매장·리뷰 공유, 본인 리뷰 삭제 권한, 서버 재시작 후 보존을 검사합니다. 테스트는 실제 이메일을 발송하지 않습니다.

## 네이버 반경 5km 식당 가져오기

기준 주소는 **경기도 화성시 동탄기흥로 614, 더퍼스트타워2차**입니다. 네이버 공식 지역 검색 API 연결 정보 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`과 `openapi.naver.com` HTTPS 접근이 필요합니다. 키 값은 채팅이나 Git 대신 환경 설정에 입력하세요. Maps 서비스 키와 검색 API 키는 서로 다를 수 있으므로 네이버 개발자센터에서 지역 검색 사용 권한을 확인해야 합니다.

```sh
npm run import:naver
# 결과 검토 후 실제 서버 DB 등록:
npm run import:naver -- --apply
```

첫 실행은 `.local/naver-import-report.json`에 검토용 결과를 저장하며 DB에 쓰지 않습니다. `--apply`는 검색을 다시 실행해 모든 API 요청이 성공하고 회사 좌표가 하나로 확인된 경우에만, 실제 서버의 `.local/dining.sqlite`에 트랜잭션으로 등록합니다. 이름과 주소가 같은 매장은 기존 직원 등록 매장과도 중복 등록하지 않습니다. 재실행으로 리뷰나 기존 매장을 삭제하지 않습니다.

회사 이름과 도로명 주소가 일치하는 유일한 검색 결과의 WGS84 좌표를 사용합니다. 좌표 형식이나 회사 위치가 불명확하면 중단하며 임의 좌표를 넣지 않습니다. 주변 동네·음식 종류별 검색 후보에서 실제 좌표를 확인하고 직선거리 5,000m를 초과하는 매장과 카페를 제외합니다. 네이버 지역 검색의 결과 수 제한 때문에 **반경 안의 모든 식당을 망라하지 않습니다**. 직선거리는 도보·차량 경로나 네이버 길찾기 거리와 다릅니다.

출처·수집 시각·회사 기준 좌표·매장 좌표·직선거리를 보존합니다. 메뉴·가격·도보 시간·단체석·주차·예약은 검색 응답에 없는 경우 미확인으로 두며 임의로 채우지 않습니다. 초기 화면은 전체 맛집을 표시해 도보 시간이 미확인인 수입 매장도 볼 수 있도록 했습니다. 정적 미리보기에는 계속 가상 데이터만 포함합니다.

현재 실제 네이버 접속과 식당 수집은 연결 설정이 없어 검증하지 못했으며 실제 식당은 업로드하지 않았습니다. 반경·중복·회사 좌표 오인식 방지는 로컬 테스트 데이터로 검증합니다.

### API HUB 인증 방식 확인

현재 사용자가 등록한 서비스는 NAVER API HUB입니다. `NAVER_API_PROVIDER`는 기본값이 `apihub`이며, 인증 화면에 명시된 `X-NCP-APIGW-API-KEY-ID`, `X-NCP-APIGW-API-KEY` 헤더를 사용합니다. 공식 지역 검색 API 요청 URL을 확인해 `NAVER_LOCAL_SEARCH_URL`에 설정해야 하며, 미설정이면 외부 요청 전에 중단합니다. `nmap://` URL Scheme은 네이버 지도 앱을 여는 기능이므로 데이터 수집 주소로 쓰지 않습니다. 관리 콘솔 주소도 사용할 수 없습니다. 기존 개발자센터에서 발급한 키만 `NAVER_API_PROVIDER=legacy`로 사용합니다.

사용자가 제공한 URL Scheme 문서의 열람은 현재 프록시 403으로 차단되어 실제 API HUB 요청 주소를 확인하지 못했습니다. 저장된 키의 실행 환경 적용, 문서 열람, 실제 요청 호스트의 네트워크 및 시크릿 허용 목적지 설정이 필요합니다. 시크릿 목적지는 실제 API HUB 호스트를 확인한 뒤 갱신해야 하며 기존 `openapi.naver.com` 설정만으로 API HUB 인증이 되는 것으로 간주하지 마세요. 새 목적지 설정은 환경 설정에서 기존 시크릿을 수정해야 할 수 있습니다. 키를 소스나 문서에 복사하지 마세요.
